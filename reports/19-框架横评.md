# Day 19｜四个评测框架横向比较

## 一眼看懂

四个框架都能组织数据、调用模型并算分，但侧重点不同。本项目已经**实际运行** `lm-evaluation-harness` 和 `OpenCompass`；对 `Inspect AI`、`EvalScope` 的描述来自各自官方文档，尚未在本机实跑。下表的“适合”是根据公开能力和本项目任务做的选型判断，不是速度或精度排名。

| 框架 / 维护方 | 任务怎么定义 | 模型入口（官方文档明示） | 结果与主要用途 | 本项目中的取舍 |
| --- | --- | --- | --- | --- |
| [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) / EleutherAI | 以 YAML 配置数据集、prompt、选项、指标、filter；特殊逻辑可写 Python | 本地 Hugging Face、vLLM、SGLang、API | 标准题库及少样本语言模型评测；可保存逐题样本 | 本项目主框架，已有 ARC、MMLU、GSM8K、C-Eval 等结果。改动 YAML 很方便，但要逐项核对任务版本、答案抽取与样本聚合。 |
| [OpenCompass](https://opencompass.readthedocs.io/en/stable/get_started/quick_start.html) / OpenCompass 开源项目 | Python 配置模型与数据集；数据集配置含 reader、prompt、推理和评分等组件 | 本地 Hugging Face、vLLM/LMDeploy、API；SGLang 服务可经兼容 API 接入，不能据此视作本机原生后端已验证 | 较丰富的模型和题库预置配置；配置、推理、评分、汇总的完整流程 | 本机已跑 C-Eval 19 题。配置灵活，但依赖、数据格式及候选评分口径需要额外排查。 |
| [Inspect AI](https://inspect.aisi.org.uk/tasks.html) / 英国 AI Security Institute 与 Meridian Labs | Python `@task` 返回 `Task(dataset, solver, scorer)`；solver 可串接提示、生成、工具与多轮过程 | API 提供商，以及本地 Hugging Face、vLLM、SGLang（见[官方模型入口](https://inspect.aisi.org.uk/providers.html)） | 逐步记录与复核多轮、工具调用、Agent 任务；也能做常规题库 | 若后续要评测“会调用工具的系统”，任务、solver、scorer 的拆分更贴题；需另写任务和检查评分记录。 |
| [EvalScope](https://github.com/modelscope/evalscope) / ModelScope 社区 | CLI 或 Python `TaskConfig`；可用内置题库、自定义数据/指标及其他评测后端 | 本地模型、OpenAI 兼容 API；文档列有 Hugging Face、vLLM、SGLang 参数支持 | 能做模型能力评测、Agent 评测、推理服务压测及可视化报告 | 如果要把准确率、API 吞吐/时延和多种模型放在同一套流程里，值得试用；接入其他后端时仍须确认实际使用的是哪套题目与评分器。 |

**后端提醒：**“支持 vLLM/SGLang”只说明存在模型调用路径，不等于本项目已在 Windows 上安装、运行或完成相同数值的对拍。尤其 OpenCompass 的 SGLang 这里指通过服务 API 接入。四个框架的官方说明分别见 [lm-eval README](https://github.com/EleutherAI/lm-evaluation-harness)、[OpenCompass 模型配置](https://opencompass.readthedocs.io/en/stable/user_guides/models.html)、[Inspect 模型入口](https://inspect.aisi.org.uk/providers.html)、[EvalScope README](https://github.com/modelscope/evalscope)。

## 本机实践：已经跑了哪两个

1. `lm-eval`：Day 6 记录了三款 Qwen2.5 base 模型 × 五项任务的有限样本试跑，见[主结果表](../results/main_table.md)和[运行台账](../RUNS.md)。Day 8–9 还自定义了 C-Eval 任务并与内置任务对拍。
2. `OpenCompass 0.5.4`：用固定 revision 的 Qwen2.5-1.5B base 跑 C-Eval 计算机网络 `val` 19 题、5-shot PPL，得到 **15/19（78.95%）**。逐题预测、评分文件和配置在[实跑报告](19-opencompass-qwen15-ceval19.md)。同题的 `lm-eval` 5-shot 为 **14/19（73.68%）**，但 prompt、候选评分和并列处理不同；不能把 1 题差距解释为某框架更准。

## 怎样选

- **继续当前静态题库项目：**沿用 `lm-eval`，保留 YAML、模型 revision、数据切分、样本日志和汇总口径；它已形成完整本地证据链。
- **核对另一套预置评测方案：**用 `OpenCompass`，先比较题目、few-shot 示例、prompt、评分器、并列规则，再比较分数。
- **测多轮工具调用或 Agent 行为：**优先试 `Inspect AI` 或 `EvalScope` 的 Agent 模式，评测对象应包含工具环境和执行轨迹，不能只看最终答案。
- **测服务吞吐、时延：**可用 `EvalScope` 的性能测试功能；本项目 Day 18 的异步脚本只做过小规模 API 并发实验，不能代替标准服务压测。[EvalScope 官方说明](https://github.com/modelscope/evalscope)

不论选哪一套，要复现同一个分数，至少固定：模型及权重 revision、数据集及版本/切分/抽样、few-shot 示例及 seed、完整 prompt/chat template、候选评分或生成参数、答案抽取与指标、框架版本。只写“Qwen2.5-1.5B 在 MMLU 得 66%”无法判断实验是否相同。公开结果的实际对照见[另一份 Day 19 报告](19-对齐公开结果.md)。
