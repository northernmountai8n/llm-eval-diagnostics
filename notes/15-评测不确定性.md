# Day 15｜评测不确定性：同一个分数，究竟有多稳？

> 整理于 2026-10-07。本日是理论与已有结果核对，**没有新增模型运行**。本文中的置信区间在“题目可看作从目标题目总体随机抽样”等前提下解释；本项目的 `--limit 200` 实际取前 200 题，不能把该区间直接当作完整 benchmark 的严格保证。

## 先区分两个问题

**问题 A：同一批题重跑，分数会不会变？**把下面的模型、数据、提示词、推理和判分设置都固定，使用确定性推理时，通常得到同一分数。若开启生成抽样，或换 seed 导致 few-shot 示例变化，重跑分数可能变。这里研究的是**评测过程自身的随机性**。

**问题 B：只测 200 题，能否代表更多题？**即使问题 A 的分数每次都一样，换一批题仍可能得到另一分数。这里研究的是**有限样本造成的估计不确定性**。分数“可复现”与“对更大题目总体估得准”是两件事。

## 想复现同一个分数，要固定什么？

| 部分 | 具体要固定的内容 | 变了会怎样 |
| --- | --- | --- |
| 模型和运行环境 | 模型名称与**权重 revision**、base/instruct 版本、tokenizer、精度（如 `bfloat16`）、设备、`lm-eval`/`transformers` 版本；批大小也要记录 | 同名模型的不同权重、分词或数值精度可能改变选项分数或生成结果 |
| 测试数据 | 数据集版本、子集、`split`、**具体题号及顺序**、`--limit`、标准答案 | 换题或换答案，最终平均分自然可能变；`--limit 200` 在本项目取前 200 题 |
| 输入提示词 | 任务 YAML、题干与选项格式、空格和分隔符、`num_fewshot`、**实际抽到的示例及顺序**、system prompt、chat template | 模型看到的文字不同，就不是同一次评测口径；只固定 few-shot seed 还不如核对最终 prompt 可靠 |
| 推理设置和随机性 | `output_type`、`do_sample`、temperature、`top_p/top_k`、最大生成长度、停止词，以及实际使用的各个 seed | 开启抽样时温度和 seed 会影响生成；`do_sample=false` 的确定性生成一般不进行温度抽样。多选 `loglikelihood` 直接比较选项似然，温度不是这项判分的生成参数 |
| 判分设置 | 答案抽取正则、filter、`acc` 还是 `acc_norm`、归一化规则、聚合方法 | 即使模型原始回答一样，换抽取或指标也可能得到另一分数 |

**固定温度和 seed 只是清单中的两项。**要确认两次运行真的一样，最好保存 `results_*.json` 和 `--log_samples`，逐题比对 `doc_id`、完整 prompt、模型原始响应和抽取后响应。GPU 等底层计算在某些环境中仍可能有微小非确定性；因此应说“通常可复现”，不要承诺任何机器上逐位相同。

| 来源 | 哪个环节变化 | 本项目对应情况 | 怎样测 |
| --- | --- | --- | --- |
| 生成抽样 | 同一输入下采样出不同 token | 多选 loglikelihood、`do_sample=false` 的既有实验通常没有这项采样 | 固定题目和 prompt，多次生成 |
| few-shot seed | 选入提示词的示例可能变化 | GSM8K 5-shot、ARC-Easy 5-shot 可检查逐题 prompt 是否真的改变 | 固定测试题，只换 few-shot seed |
| 题目样本 | 换了一批测试题 | 现有 `--limit 200` 是取前 200 题，没有随机抽题 | 对题目重采样、bootstrap，或使用预先设计的随机样本 |

改变 seed 并不自动创造波动：0-shot、固定题目、确定性推理若没有使用该随机源，五次运行可能完全一样。

## 手算：`n=200, p=0.7`

把每题“答对”记为 1，“答错”记为 0。200 题答对 140 题时，样本准确率为 `p̂=140/200=0.70`。若题目近似独立、来自要研究的题目总体，二项模型给出准确率的标准误近似：

```text
SE ≈ √[p̂(1−p̂)/n]
   = √[0.70×0.30/200]
   = √0.00105
   ≈ 0.0324 = 3.24 个百分点

95% 正态近似区间 ≈ p̂ ± 1.96×SE
                  ≈ 0.70 ± 0.0635
                  ≈ [0.6365, 0.7635]
```

也就是观察到 **70%** 时，区间宽度约为 **±6.35 个百分点**。这不是说“模型真实准确率有 95% 概率就在这个已算出的区间内”；频率学派解释是：若抽题过程和前提成立，反复抽样并按同一方法建区间，长期约 95% 的区间覆盖固定的总体准确率。对于固定的测试集前 200 题，这个区间只能帮助理解样本量量级，不能代替随机抽样设计。

可在 PowerShell 的 `lmeval` 环境核算：

```powershell
python -c "import math; p=0.7; n=200; se=math.sqrt(p*(1-p)/n); print('SE=',se,'95% CI=',(p-1.96*se,p+1.96*se))"
```

## 对照本机 `lm-eval` 的 `stderr`

Day 6 的 Qwen2.5-1.5B、ARC-Easy 0-shot、前 200 题结果文件位于 `runs/day06_qwen15_arc_easy_s0_n200/Qwen__Qwen2.5-1.5B/`：

```text
acc,none        = 0.715   （143/200 题）
acc_stderr,none = 0.03199992148231578
```

本机 `lm_eval/api/metrics.py` 对均值使用 `mean_stderr = sample_stddev(x) / √n`，其中样本标准差分母为 `n−1`。对逐题 0/1 正误，可化为 `√[p̂(1−p̂)/(n−1)]`。代入 `p̂=0.715,n=200` 得 `0.0320`，与结果文件一致。它与上节的 `√[p̂(1−p̂)/n]` 只差很小的贝塞尔校正。

以结果文件的 stderr 作正态近似，`0.715 ± 1.96×0.0320 ≈ [0.6523, 0.7777]`。框架报告的 `stderr` 是**单次分数均值的标准误估计**，不是“换五个 seed 后的标准差”，也不是“这次运行中分数自己上下跳动了 3.2 分”。

复核命令：

```powershell
python -c "import glob,json; p=glob.glob('runs/day06_qwen15_arc_easy_s0_n200/Qwen__Qwen2.5-1.5B/results_*.json')[0]; r=json.load(open(p,encoding='utf-8'))['results']['arc_easy']; print('acc=',r['acc,none'],'stderr=',r['acc_stderr,none'])"
```

## 两个模型相差 1.5 个百分点，能说谁更好吗？

如果都评同 200 题，1.5 个百分点只对应**净多答对 3 题**。先核对模型 revision、相同题目与 split、prompt、shot、答案抽取和指标；口径不同，差 1.5 分没有可解释性。

即使口径完全一致，也要看**逐题配对**：模型 B 多对 3 题，可能是“B 独对 4 题、A 独对 1 题”，也可能是“B 独对 53 题、A 独对 50 题”。净差相同，但分歧题数量不同，差值的不确定性也不同。可以对逐题正误差做配对 bootstrap，或用 McNemar 检验分析两模型分歧题；再报告差值及区间，而不是只看两个各自的 stderr。

**“两个 95% 置信区间重叠，所以差异不显著”不是严格判定规则。**尤其是同一批题的配对比较，两个单独区间的重叠情况不能替代“差值的置信区间/检验”。在没有逐题分析前，合适的说法是：**当前证据不足以判断 1.5 分差距是否稳定**，而不是武断宣称两个模型相同或某个模型更强。

## 明天做实验前要记住的边界

1. 固定同 200 题只换 few-shot seed，测到的是**提示词示例选择带来的运行间波动**；不能拿这组分数的标准差直接与二项抽样标准误相除，声称已经分离出“额外样本方差”。
2. 要讨论不同题目带来的波动，需改变抽题方案或对逐题结果重采样；要讨论生成随机性，需在固定 prompt 下多次采样生成。实验报告应注明究竟变了哪个环节。
