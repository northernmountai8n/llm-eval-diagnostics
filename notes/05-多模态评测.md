# Day 5 笔记：多模态评测从题目到分数

## 今日目标与边界

**目标**：能解释 MMMU、MMBench、MathVista 分别测什么；能沿着“图文输入 → 模型回答 → 答案提取 → 判分”排查评测问题；能回答“多模态评测比文本评测难在哪”。

**完成方式**：阅读三篇论文及官方仓库，并检查本机 `lm-eval` 的 ARC-Easy 与 MMMU 配置。**本日没有运行多模态模型，也没有多模态实测分数。**论文里的基准规模与本机配置实际评测的 split 不能混为一谈。

## 一、为什么读这三篇

它们分别补齐评测设计的三个视角：

1. **MMMU：能力覆盖与难度。**用跨学科的图文题考察视觉理解、专业知识与推理的结合。
2. **MMBench：能力拆分与评测协议。**把能力分细，并用选项轮换检查模型是否依赖选项位置。
3. **MathVista：视觉数学与开放回答。**图表、几何等题目常要求数值或其他短答案，需要从模型长回答中提取并规范化。

它们共同帮助我建立这条评测链：**想测的能力 → 数据与题型 → 图像和文本如何进入模型 → 模型回答 → 答案提取与判分 → 汇总指标与错误分析**。总分只是最后一步，前面任何一步发生变化，分数都可能变化。

## 二、三篇论文对比

下表数字使用所链接的**论文版本**，不是所有后续发布版本或排行榜的统一数字。

| 基准 | 考什么能力 | 论文版本的样本规模 | 论文中的判分方式 | 已知局限 / 解读时要问的问题 |
|---|---|---|---|---|
| [MMMU](https://arxiv.org/html/2311.16502v4) | 大学层面的多学科图文理解、知识与推理；6 大学科、30 个科目、30 类图像 | 11,550 题；dev 150、validation 900、test 10,500；约 94% 选择题、6% 开放题 | 生成回答后用规则提取答案，再算逐题正确率的 micro average；选择题无法解析时随机选项，开放题无法解析记错 | 题目广且难，但大学考试成绩不能单独证明“专家级 AGI”；错误可能来自看图、知识、推理或答案解析，需分开分析。 |
| [MMBench](https://arxiv.org/html/2307.06281v5) | 细粒度视觉能力，覆盖 20 个能力维度 | 论文 v5 报告 3,217 道选择题；使用不同数据发布版时应重新核对数量 | 模型生成回答，GPT-4 将自由文本匹配到选项；CircularEval 将选项轮换 N 次，**全部答对**才算该题正确 | CircularEval 对选项位置偏好更敏感，但比单次作答更耗调用；选项提取也会出错，论文报告 GPT-4 与人工在该提取任务上有 91.5% 一致率，并非 100%。 |
| [MathVista](https://arxiv.org/html/2310.02255v3) | 图像场景下的数学推理，如图表、几何、函数图像 | 6,141 题；testmini 1,000、test 5,141；约 55% 选择题、45% 自由回答 | 先生成回答，再用 GPT-4 等方法提取短答案，规范化为选项/数字等格式，最后算准确率 | 数学题型与视觉形式仍可能覆盖不全；源数据标注格式不统一。答案提取质量也会影响最终分数。 |

论文与代码入口：[MMMU 官方仓库](https://github.com/MMMU-Benchmark/MMMU)、[MMBench 官方仓库](https://github.com/open-compass/MMBench)、[MathVista 官方仓库](https://github.com/lupantech/MathVista)。

**口径提醒**：这三个“准确率”不能直接横向比较。题目、split、提示词、是否轮换选项、答案提取器都不一样。尤其不能把 MMBench 的 CircularEval 分数当成普通单次选择题准确率。

## 三、对照我已经跑过的 ARC-Easy

Day 4 的实验是 **Qwen2.5-1.5B + ARC-Easy 前 500 题**：0-shot `acc=75.2%`，5-shot `acc=79.8%`。这里只能说明同一模型在当前题目和设置下，shot 数改变了分数；它**不是**多模态实验。详情见 [Day 4 笔记](04-fewshot与prompt.md)。

本机 `lmeval` 环境中的任务配置显示出关键区别：

| 环节 | ARC-Easy（本机 `arc_easy.yaml`） | MMMU（本机 `mmmu/_template_yaml` 与 `utils.py`） |
|---|---|---|
| 输入 | `doc_to_text` 组织纯文本问题；`doc_to_choice` 给出候选答案 | `doc_to_text` 组织含图像占位符的问题；`doc_to_image` 按占位符顺序取出图像，可能一题多图 |
| 模型调用 | `output_type: multiple_choice`，对候选文本分别算 loglikelihood | `output_type: generate_until`，让视觉语言模型生成文本回答 |
| 判分 | `acc` / `acc_norm`，按候选分数排序与标准答案比对 | `process_results` 解析生成文本中的选择题或开放题答案，再返回 `acc` |
| 本机配置覆盖 | ARC-Easy `test`，Day 4 仅运行前 500 题 | MMMU 本机配置选 `validation`；`mmmu_val` 组覆盖 **900 题**，不是论文全量 11,550 题 |

**源码观察**：本机 MMMU 的 `doc_to_image` 依据文本中的 `<image 1>` 等标记收集图像；`process_results` 对选择题和开放题走不同解析函数。选择题实在解析不出时，本机代码会随机选一个选项。因此即使输入模型的能力没变，图像对应关系、解析规则、随机回退也可能改变分数。检查本机文件：`D:\program\miniconda\envs\lmeval\Lib\site-packages\lm_eval\tasks\mmmu\_template_yaml`、`utils.py`、`_mmmu.yaml`，以及 `...\tasks\arc\arc_easy.yaml`。

本机安装的 `lm_eval/tasks` 中没有找到 MMBench 和 MathVista 的 YAML；本日只检查了 MMMU 的多模态任务定义，没有声称三者都已在本机跑通。

## 四、多模态评测的三个工程难点

### 1. 图像分辨率、切片与视觉 token 预算

图片不一定作为一个固定长度的输入进入模型。具体模型可能缩放图片、编码成多个视觉 patch，或在高分辨率处理时切成多个区域；**切片不是所有模型必用的同一实现**。分辨率或切片方案变化，可能一边让小字、图表细节更可见，一边增加视觉 token 数、显存占用与推理时间。[Qwen2-VL 官方模型卡](https://huggingface.co/Qwen/Qwen2-VL-2B-Instruct/blob/main/README.md)明确允许通过 `min_pixels` / `max_pixels` 控制图像大小，并给出视觉 token 数与速度、显存的权衡示例。

评测记录应包含：图像尺寸、缩放/裁切规则、最多图像数、视觉 token 或像素预算、processor 和模型版本。对多图、细小文字或密集图表要重点抽查：模型实际收到的图是否完整、图像顺序是否和问题中的引用一致。

### 2. 批量推理中的图像预处理

文本批处理主要处理长度差异；图文批处理还要读图、解码、缩放、裁切/patch 化，并处理每题图像数量和尺寸不同的问题。这会增加 CPU 预处理、内存搬运和 batch 拼接的时间，也可能让一个 batch 的显存需求由最大或最复杂样本决定。**这是根据输入处理流程作出的工程推断，不是本项目测得的瓶颈结论。**

若以后实测，应分别记录“读图/预处理耗时、模型前向或生成耗时、每秒完成题数、显存峰值”，再判断瓶颈是否真在预处理；不要只看 GPU 利用率猜原因。图片问题也不能简单照搬 ARC-Easy 的 `batch_size=1` 速度数据。

### 3. 答案提取器与 judge 成本

开放式回答可能把正确结果写在一段解释里，直接字符串匹配会误判；规则提取便宜、可复现，但覆盖不了所有表达。MMMU 论文主要采用**规则解析**。MMBench 用 GPT-4 把模型回答匹配到选择题选项；MathVista 用 GPT-4 等方法提取短答案，再规范化判分。这两处的 GPT-4 更准确地说是**答案提取器**，不是每题都做开放式质量裁判。

使用 LLM 提取器会带来额外调用费用、等待时间和输出不稳定性；MMBench 的 CircularEval 还可能让同一题生成多次。算成本时需分开记：被测模型调用次数、答案提取器调用次数、各自 token 用量与价格。复现分数时还要固定提取器版本、提示词、温度，并保留原始回答和提取后的答案。论文的提取准确率并不意味着新模型、新回答格式或新数据上必然同样准确。

## 五、如果以后做一次多模态实验，我会怎样检查

1. **先定任务**：明确是要测跨学科知识、细分视觉能力，还是视觉数学；选择对应 benchmark 和明确的 split。
2. **锁定输入**：记录题目 ID、原图与送入模型的图、图像顺序、resize/crop/tiling 设置、模型及 processor 版本。
3. **锁定协议**：记录 prompt、shot 数、生成参数、选项是否轮换、每题允许几次调用。
4. **锁定判分**：保存原始生成、提取后的答案、标准答案、解析失败标记、judge 或提取器版本。
5. **看逐题错误**：先抽查一批“模型似乎答对但被判错”的样本，再区分看图失败、知识欠缺、推理失败和答案提取失败。
6. **报告结果**：写清 benchmark 版本、split、题数、指标和预处理方式；只对相同协议下的结果作比较。

## 六、面试题：多模态评测比文本评测难在哪？

> 文本评测已经要控制题目、prompt、shot 数和评分规则；多模态还多了一条图像处理链。图片的缩放、裁切或切片会影响模型看到的细节、视觉 token 预算和推理成本；不同大小、不同图像数的样本也使批量推理更复杂。模型通常生成自由文本，因此还要从回答里可靠地提取选项或数值，必要时调用 LLM 提取器，这会增加成本并引入解析误差。做评测时我会保留原图与处理配置、原始回答和提取结果，分析错误到底出在视觉输入、模型推理还是判分环节。

## 八、加餐阅读：一篇综述如何串起前三篇

**选读**：[MME-Survey: A Comprehensive Survey on Evaluation of Multimodal LLMs](https://arxiv.org/html/2411.15296)（arXiv:2411.15296v2，2024-12-08）。选它是因为文章专门讨论**评测**，而不是主要介绍模型结构；作者把基准类型、数据构建、judge、指标与工具放在同一框架中，正好帮助整理本日三篇论文。它是文献综述，下面是从综述归纳的方法，**不是本项目新做的实验结果**。

### 我记住的四层框架

| 先问什么 | 综述的主要内容 | 对我的实际用途 |
|---|---|---|
| **测什么？** | 基础能力、模型自身行为（如幻觉与安全）、扩展应用；基础能力下还能细分 OCR、图表、数学、多学科、多图等 | 先确定能力目标，再选基准；MMBench 偏细分能力，MMMU 偏多学科知识与推理，MathVista 偏视觉数学。 |
| **题怎么来？** | 数据收集、标注，以及数据泄漏、选择题捷径、样本量等问题 | 看见高分时，要问题是否出现在训练资料中、选项是否泄漏答案、样本是否足够。 |
| **怎么判？** | 人工、LLM/MLLM 和脚本三类评判方式；确定性指标与非确定性评分/比较 | MMMU 的规则解析、MMBench/MathVista 的模型辅助答案提取，都处在这层；**提取答案**和**让 judge 主观打分**是两件不同的事。 |
| **怎么复现？** | 多模态评测工具需要组织模型、数据集、推理、判分与结果 | 同名任务也要核对 split、提示词、图像处理和评分实现，不能只抄排行榜分数。 |

综述给前三篇带来的**两个新提醒**：

1. **检查题目是否真的依赖图像。**综述指出，一些所谓图文题可能只靠文字和选项就能答对。以后做实验，可在同一批题、同一提示词与评分规则下，增加“去掉图片”的文本基线，并比较逐题变化。若无图仍大量答对，不能把全部正确率解释为视觉能力；但也不能仅凭无图分数断定发生了训练数据泄漏。
2. **把判分误差当作独立问题。**脚本规则快速、便宜，但可能漏掉正确的自由表达；模型辅助提取更灵活，但有调用成本和偏差。应保留原始回答、提取结果和人工抽样核对记录，才知道分数变化发生在哪一步。

**读综述时的核对习惯**：综述覆盖面广，具体协议仍以原论文和当前任务实现为准。例如综述把 CircularEval 概述为选项多次重排，而 [MMBench 原论文](https://arxiv.org/html/2307.06281v5)明确采用**循环移位**，且须各轮全对。复现时按原论文及实际代码记录选项变换，不把“任意随机打乱”和“循环移位”当成同一个协议。
